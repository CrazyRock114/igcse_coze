## What makes this different

Every interaction is anchored to a specific syllabus statement. The home page is the
statement map with coverage marked on it, not a gallery of simulations — so you can
always answer "which parts of the exam does this actually teach?"

Three strands:

1. **Learn** — interactive simulations with bilingual narration, tiered Core / Extended
2. **Practise** — exam-style questions with mark schemes and command-word coaching
3. **Investigate** — Paper 5/6 practical skills, which are 20% of the grade *(planned)*

`npm run check:syllabus -- --min 80` additionally fails below 80% coverage.

The two checks divide the work by consequence. `check:content` catches what would break
a lesson at runtime and gates the build. `audit` catches what would leave a lesson
quietly wrong — a checkpoint tiered Core that tests Supplement material, a glossary
entry citing a statement its lesson does not teach — and is run deliberately, because
some of what it reports is a judgement call.

## Architecture

The rule everything follows from: **course copy is data, never JSX.**

A lesson is a `Lesson` object in `src/content/lessons/<subject>/<slug>/lesson.ts`. One
generic renderer (`components/lesson/LessonPage.tsx`) draws every lesson in the course.
Adding a lesson means adding a directory — there is no central catalogue to update,
because `lib/registry.ts` discovers content with `import.meta.glob`.

```
src/
├─ content/                    Content as typed data
│  ├─ types.ts                 Lesson, SimSpec, Question, NarrationScript, Bilingual
│  ├─ syllabus/                index.ts registry + one file per subject
│  ├─ lessons/<subject>/<slug>/
│  │  ├─ lesson.ts             Manifest: bilingual copy, syllabus refs, sim config
│  │  ├─ kernel.ts             Pure science — no DOM, no React
│  │  ├─ kernel.test.ts        Required. Proves the drawing matches the equations.
│  │  └─ narration.ts          EN/ZH script; lines can drive the simulation
│  └─ questions/               Exam-style banks with mark schemes
├─ sim/                        Reusable simulation primitives
├─ components/                 Generic renderers — i18n, lesson, narration, assessment
└─ lib/                        i18n, units, formulae, field lines, registry
```

### Why it is built this way

The reference projects this course learned from (mathviz, ChemAIForge and the
`whaty.org` family) proved the interaction model but hit two walls we deliberately
avoid:

- **No monolithic registry.** Their `catalog.ts` reached ~100 KB and every new
  experiment had to be registered in several places. We use filesystem discovery.
- **No copy inside components.** Their lesson text was hard-coded Chinese inside each
  `.tsx`, which made the content untranslatable after the fact. Here an ESLint rule
  rejects CJK literals in `src/components/**` and `src/sim/**`.

### Bilingual model

English is required by the `Bilingual` type; Chinese is optional. Chinese never
replaces English — a student who read only the Chinese would not be prepared to sit
the paper.

Three assist levels, persisted to `localStorage`:

| Level | Behaviour |
| --- | --- |
| `off` | English only. Exam-condition mode. |
| `hover` | English, Chinese on hover. Default. |
| `inline` | English with Chinese alongside. |

**Question stems are English only, by design** — students must practise reading exam
questions in the language of the exam. Chinese support lives in the command-word
hints and examiner's notes, which explain *how to answer*, not *what is asked*.

### Simulation kernels

Kernels are pure functions: parameters in, series and readouts out. That makes the
science unit-testable on its own, and lets tests assert that the numbers on the graph
are the numbers in the equations.

The tests are written to catch content being *wrong*, not merely absent. Some examples:

- `1-2-motion` integrates the speed–time curve and checks the area equals the reported
  distance — the exact claim the lesson makes to the student (0625.1.2.7).
- `4-5-induction` asserts the induced e.m.f. peaks where the flux through the coil is
  zero. The lesson was first written with that geometry reversed.
- `2-6-giant-structures` generates the atom positions and works the bonds out by
  distance, so "four bonds in diamond, three in graphite" is checked rather than drawn.
- `6-3-equilibrium` holds the model to published equilibrium yields at the reference's
  own tabulated points, and to clamping rather than extrapolating past its ends.
- `12-3-chromatography` asserts every Rf is unchanged when the plate is run further —
  which is the whole reason Rf is quoted instead of a distance.

## Simulation primitives

A lesson picks a primitive and configures it with data; it does not ship its own
renderer.

| Primitive | Interaction |
| --- | --- |
| `plot2d` | Sliders drive graphs on round, exam-style axes; signed axes for I–V curves; dashed reference lines for values read off the axis rather than the curve |
| `raytrace` | **Drag the incident ray**; refraction vanishes past the critical angle |
| `beam` | Move a mass without changing it — the beam still tips |
| `particles` | **Animated.** Piston compresses the gas; pressure rises |
| `waves` | **Animated.** Medium and displacement graph side by side |
| `circuit` | **Animated.** Charge drifts round the loop; dot density is current |
| `field2d` | Field lines traced by integrating the real field, so spacing means strength |
| `atom` | Electron shell diagrams; isotopes and ions from one control set |
| `molecule` | Displayed formulae built by valence, so the formula is counted off the drawing |
| `bonding` | Dot-and-cross diagrams; one control runs electron transfer and electron sharing |
| `giant` | Giant structures with bonds worked out by distance — diamond, graphite, silica, metals |
| `balance` | A chemical equation with a per-element atom tally; formulae are fixed, only coefficients move |
| `chromatogram` | A developed plate; running the solvent further moves every spot and no Rf |
| `ladder` | A list with a threshold line across it; the ordering arrow and every label are data |
| `lattice` | Rows of atoms with the upper layers pushed across the lower ones |
| `periodictable` | Periods 1–4 as a grid, coloured by category; sliding Z walks the highlight |
| `punnett` | A cross drawn from the gametes, with the ratio tallied off the grid |
| `pyramid` | Trophic levels on a logarithmic scale, so the real numbers stay readable |
| `sort` | Click an item, then its bin. A wrong placement sticks and is marked |
| `match` | One-to-one pairing; the right-hand column is deranged so writing order cannot answer it |
| `vectors` | Arrows from a common origin, with the resultant boxed |
| `apparatus`, `graphpaper` | planned — Paper 5/6 |

### Multi-subject

Lessons live under `src/content/lessons/<subject>/<slug>/` and carry a `subject` field
matching their directory; the integrity check enforces both, and rejects a lesson that
cites another subject's statement ids. Routes are `/lesson/:subject/:slug`, and the home
page has a subject switcher. Adding a subject means adding a syllabus file and one entry
in `src/content/syllabus/index.ts`.

## Deployment

Development now happens in this repository (`igcse_coze`); the legacy GitHub Pages
site (`Science_cc`) is frozen and no longer receives updates. The target platform
is **Vercel** — read **HANDOVER.md** before deploying: the `/api/tutor` SSE endpoint
is dev-server-only today and must be ported to a Vercel Function, and narration
audio generation (`gen:narration`) only runs inside the Coze sandbox. `AGENTS.md`
remains the source of truth for architecture and conventions.
